Day 3 · 装饰器：Python 的 AOP ​

前言 ​

Python 装饰器是语言的核心能力。@app.get("/")、@pytest.fixture、@lru_cache——路由、测试与缓存等大量生态 API 都建立在装饰器之上。今天的目标：从"会用"到"能手写任意形态"。

课程目标 ​

  • 理解装饰器本质：高阶函数 + 语法糖
  • 掌握 functools.wraps 保留元信息
  • 能手写：无参装饰器、带参装饰器、类装饰器、装饰器堆叠
  • 理解装饰器的执行时机（import 时！）

阅读学习 ​

  • Python 官方：functools.wraps
  • Real Python: Primer on Python Decorators（长文，值得完整读）
  • 核心心智模型：
python
@decorate
def target(): ...

# 完全等价于
def target(): ...
target = decorate(target)

任务作业 ​

  1. 计时装饰器：实现 @timer，打印被装饰函数的耗时（用 time.perf_counter）。要求支持任意参数签名的函数，且用 @functools.wraps 保留原函数的 __name__ 和 docstring。验证：不加 wraps 时 help(f) 显示什么？

  2. 带参装饰器：实现 @retry(times=3, delay=1)，函数抛异常时自动重试，重试间隔可配。理清三层嵌套函数的每一层职责——这是装饰器最难的部分，写完后画一张调用流程图放进笔记。

  3. 缓存装饰器：自己实现一个简易 @cache（不许用 lru_cache），支持设置最大容量、LRU 淘汰。然后和标准库 lru_cache 对比功能和性能。

  4. 装饰器堆叠顺序：

python
@a
@b
@c
def f(): ...

写三个打印日志的装饰器，运行后观察执行顺序，总结规律（装饰自底向上应用，执行自顶向下包裹）。

  1. 注册模式：模仿 Flask，实现一个迷你路由框架：
python
routes = {}

@route("/hello")
def hello(): return "Hello!"

# route("/hello")() 应该返回 "Hello!"

理解"装饰器在 import 时执行注册"这一模式——这是无数框架的基石。

自测问题 ​

  • 装饰器在什么时候执行？定义时还是调用时？（对理解框架的 import 副作用至关重要）
  • 没有 @functools.wraps 会丢什么元信息？为什么 FastAPI 之类框架必须用它？
  • 带参装饰器为什么是三层函数嵌套？每一层分别接收什么？
  • 如何给装饰器本身写单元测试？
  • 用类实现装饰器（__call__）和用函数实现，各自适合什么场景？

总结 ​

拓展阅读 ​

  • PEP 318：Decorators for Functions and Methods
  • 读一读 Flask 或 FastAPI 源码中路由装饰器的实现
