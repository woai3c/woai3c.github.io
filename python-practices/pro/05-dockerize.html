Day 5 · Docker 化 Python 应用 ​

前言 ​

Docker 化 Python 应用需要处理多阶段构建、依赖锁定、镜像最小化与非 root 运行。本课将重点处理 uv 的依赖安装方式，以及 gunicorn/uvicorn 这类 WSGI/ASGI 服务器的容器运行方式。

课程目标 ​

  • 写出生产级的 Python Dockerfile（多阶段构建）
  • 掌握 uv 在容器内的最佳实践
  • 镜像体积优化：slim / alpine 的取舍
  • 掌握 Python 容器的健康检查与优雅退出

阅读学习 ​

  • uv 官方：Docker 集成指南（权威实践）
  • Docker 官方：Python 镜像最佳实践
  • 对照速览：
Node Dockerfile 实践Python 对应实践
node:22-slim 基础镜像python:3.12-slim（alpine 慎用，musl libc 编译坑多）
npm ciuv sync --locked（严格按 uv.lock 安装）
构建期 node_modules 不拷贝进最终镜像.venv 在多阶段间拷贝
node dist/server.jsuvicorn app:app --host 0.0.0.0
dumb-init / tini 处理信号同样需要（Python 对 SIGTERM 的处理也要验证）

任务作业 ​

  1. 多阶段 Dockerfile：为进阶班 Day 4 的 FastAPI 应用编写生产 Dockerfile：
dockerfile
# 参考骨架，请完善细节
FROM ghcr.io/astral-sh/uv:python3.12-bookworm-slim AS builder
# ... uv sync --locked --no-dev ...

FROM python:3.12-slim
# ... 拷贝 .venv，非 root 用户，启动命令 ...

要求：锁定依赖、不安装 dev 依赖、非 root 运行、启用 BuildKit 缓存挂载（--mount=type=cache）加速重复构建。

  1. 镜像体积优化：记录初始镜像大小，然后通过以下手段逐步优化并记录每一步的体积变化：

    • slim 基础镜像
    • 多阶段构建丢弃构建工具链
    • .dockerignore（排除 .venv、.git、tests、docs）
    • --no-compile 等 uv 优化选项

  2. 信号处理实验：在 FastAPI 应用中加入启动/关闭钩子（lifespan），打印日志。用 docker stop 观察应用是否优雅退出（收到 SIGTERM → 完成进行中请求 → 退出），对比 PID 1 问题：直接 CMD ["python", "main.py"] vs exec 形式的差异。

  3. docker-compose 全家桶：写 compose.yaml：FastAPI 应用 + Redis + Postgres，应用通过环境变量连接，配置 healthcheck 与依赖顺序（depends_on + condition: service_healthy）。

自测问题 ​

  • 为什么 Python 镜像通常不选 alpine？（提示：manylinux wheel 与 musl）
  • .venv 能从 builder 阶段直接拷贝到运行阶段吗？路径必须一致吗？
  • uv sync --locked 和 uv pip install -r requirements.txt 在可复现性上有何差异？
  • 为什么容器里要监听 0.0.0.0 而不是 127.0.0.1？
  • 生产环境用 uvicorn 单进程还是 gunicorn -k uvicorn.workers.UvicornWorker 多进程？与 GIL 知识联系起来。
