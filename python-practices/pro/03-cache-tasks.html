Day 3 · 缓存与后台任务：Redis 与 Celery ​

前言 ​

本课使用 redis-py 完成异步缓存访问，使用 Celery 运行后台任务，并用 Redis 作为 broker。我们会从缓存模式和队列语义开始，逐步建立完整的实现。

课程目标 ​

  • 熟练使用 redis-py 异步客户端
  • 掌握缓存模式：cache-aside、TTL 策略、缓存穿透/雪崩防护
  • 掌握 Celery 任务队列与 FastAPI 的集成（生产主流方案）
  • 亲手踩一遍 Celery 同步 worker 里跑 async 代码的坑

阅读学习 ​

  • redis-py 官方文档（asyncio 部分）
  • Celery 官方：First Steps（重点学习）
  • 对照速览：

任务作业 ​

  1. cache-aside 模式：给任务 API 的列表接口加缓存：
python
async def get_tasks_cached(user_id: int) -> list[TaskOut]:
    if cached := await redis.get(f"tasks:{user_id}"):
        return TaskOut.parse_cached(cached)
    tasks = await query_db(user_id)
    await redis.set(f"tasks:{user_id}", serialize(tasks), ex=60)
    return tasks

处理写操作的缓存失效（创建/更新/删除任务时删 key），并记录缓存命中与回源数据库时的执行路径。

  1. 手写缓存装饰器：用你基础班学的装饰器功力，实现一个 @cached(ttl=60, key_prefix="...") 通用缓存装饰器，自动序列化返回值（JSON）、自动拼接函数参数进 key。这是装饰器+Redis 的完美结合。

  2. 缓存穿透与雪崩（设计题，写实现+注释说明）：

    • 穿透：查询不存在的 id 打穿缓存到 DB → 用"空值缓存"或布隆缓解
    • 雪崩：大量 key 同时过期 → 给 TTL 加随机抖动（ex=60+random.randint(0,10)）

  3. Celery 任务队列：用 Celery + Redis broker 实现"批量导入任务"：提交 CSV → API 立即返回 task_id → worker 进程异步逐行处理 → GET /jobs/{task_id} 查询进度。要求：

    • worker 与 API 是两个独立进程（体会 celery -A app worker）
    • 任务带重试（autoretry_for、max_retries）与超时（soft_time_limit）
    • 注意：Celery 任务是同步函数，若在任务里调用 async 代码需要 asyncio.run()——亲手踩一次这个坑，你就理解了"为什么 asyncio 原生队列会出现"
    • 用 Celery 的 AsyncResult 查询任务状态与结果

自测问题 ​

  • Celery 为什么是同步 worker 模型？在 Celery 任务里跑 async 代码有哪些方案，各自的坑？
  • cache-aside 模式中，"先删缓存再写库"和"先写库再删缓存"哪个更稳？（经典并发题）
  • 消息队列的 at-least-once 语义意味着什么？消费者为什么要幂等？
  • Redis 同时当缓存和 Celery broker 时，为什么要用不同的逻辑数据库（db0/db1）？
  • 队列任务和 FastAPI 自带的 BackgroundTasks 有什么区别？各自适用场景？
