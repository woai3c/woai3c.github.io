毕业设计 · 多用户任务协作平台：从 0 到 1 上线 ​

前言 ​

终极任务，没有阅读材料、没有步骤分解——只有需求、验收标准，和你在这 24 个任务里积累的一切。把它当作一个真实的商业项目来对待。

项目背景 ​

构建并上线一个多用户任务协作平台（可以理解为迷你版 Linear/Trello 的后端）：团队管理任务、实时协作、异步通知。功能本身不新鲜——新鲜感在于你要用全新的技术栈，以生产级标准独立完成全链路。

功能需求 ​

核心领域

  1. 用户体系：注册、OAuth2 + JWT 登录（access + refresh token 轮换）
  2. 团队与权限：用户可创建团队、邀请成员；角色分 owner/member，接口级权限控制（scopes）
  3. 任务管理：任务属于团队和项目，支持指派、状态流转（todo/doing/done）、优先级、截止时间
  4. 评论与动态：任务下可评论；关键操作（创建/指派/完成）产生动态流

实时与异步

  1. WebSocket 实时推送：任务状态变更、新评论实时推送给在线的团队成员（FastAPI 原生支持 WebSocket，配合 Redis pub/sub 做跨实例广播）
  2. 异步通知：任务被指派/临期时，通过 Celery 队列异步发送通知（邮件可 mock，写入通知表即可），支持失败重试

数据与缓存

  1. PostgreSQL 持久化：SQLAlchemy 2.0 + Alembic 迁移，关系建模（用户/团队/项目/任务/评论/通知）
  2. Redis 缓存：任务列表、动态流的 cache-aside 缓存与正确的失效策略

工程质量

  1. 完整类型标注，mypy strict 通过；ruff 零告警
  2. pytest 覆盖率 ≥ 70%：认证、权限、任务流转、缓存失效必须有测试
  3. pydantic-settings 配置 + structlog 结构化日志（带 request_id）+ /metrics 指标端点

部署运维

  1. 生产级 Dockerfile（多阶段、非 root、锁定依赖）
  2. compose.yaml 一键起全套：app + worker + Postgres + Redis
  3. K8s 清单：app 与 worker 分离的 Deployment + Service + HPA + 探针 + 资源限额
  4. CI：pre-commit + GitHub Actions（lint / typecheck / test / build image）

架构提示（不强制） ​

┌─────────┐   HTTP/WS   ┌─────────────┐   SQL    ┌────────────┐
│  Client  │ ◄────────► │ FastAPI app  │ ──────► │ PostgreSQL │
└─────────┘             │  (n replicas)│          └────────────┘
                        │              │   ┌────► │   Redis    │
                        └──────┬───────┘   │      │ cache+queue│
                               │ enqueue    │      └─────┬──────┘
                        ┌──────▼───────┐   │            │ pop job
                        │ celery worker │ ◄─┴────────────┘
                        └──────────────┘

WebSocket 跨实例广播是本项目最难的点：多副本下，A 实例上的操作要推给连在 B 实例上的用户——Redis pub/sub 是标准解法。

验收清单 ​

  • [ ] 本地 docker compose up 一键运行，README 有清晰说明
  • [ ] 两个浏览器会话（不同用户）能通过 WebSocket 实时看到对方的任务变更
  • [ ] 异步通知可观测：提交任务后能追踪 job 状态
  • [ ] kubectl apply 到本地 kind 集群后服务可用，滚动更新不中断请求
  • [ ] CI 全绿
  • [ ] 一篇项目复盘笔记：架构决策、踩坑记录、如果重来会怎么做

结语 ​

从预备班敲下第一行 uv init，到今天独立上线一个生产级的 Python 后端服务——你已经完成了从 "Python 零基础" 到 "Python 后端工程师" 的转变。

但请记住学园介绍里的那句话：这里只是个辅助，一切的成长和进步一定依赖于你自己，也归功于你自己。

恭喜你，毕业了。
