Day 3 · 类型提示：Python 界的 TypeScript ​

前言 ​

作为 TS 用户，你会在 Python 类型提示里找到强烈的既视感：list[str] 像 string[]，str | None 像 string | null，mypy 像 tsc。最大区别：Python 类型运行时默认无效（会被擦除），但 pydantic 这类库又能在运行时利用类型做校验——这是 TS 做梦都想要的能力。

课程目标 ​

  • 掌握 typing 核心语法：联合、可选、泛型、Protocol、TypeVar
  • 熟练使用 pydantic 做运行时数据校验
  • 理解结构化类型（duck typing 的静态化）
  • 配置 mypy 严格模式

阅读学习 ​

  • Python 官方：typing 模块
  • pydantic 官方文档（v2 版本）
  • 对照速览：

string[]list[str]
string | nullstr | None 或 Optional[str]
Record<string, number>dict[str, int]
interface（结构化）Protocol（结构化！）
class 声明TypedDict / pydantic BaseModel

函数类型 (a: number) => voidCallable[[int], None]
unknownAny 的安全替代是 object

任务作业 ​

  1. 类型迁移练习：把下面这段 TS 代码逐行翻译成带完整类型标注的 Python：
typescript
interface User { id: number; name: string; email?: string }
function findUser(users: User[], id: number): User | undefined { ... }
function groupBy<T>(items: T[], key: keyof T): Record<string, T[]> { ... }

要求：findUser 用 User | None，groupBy 用 TypeVar 实现泛型。用 mypy strict 模式验证零报错。

  1. pydantic 实战：为一个 LLM API 的请求体建模：
python
class ChatRequest(BaseModel):
    model: str
    messages: list[Message]  # role + content
    temperature: float = Field(default=0.7, ge=0, le=2)
    max_tokens: int | None = None

要求：嵌套模型、字段校验、默认值、自定义 validator（比如 messages 不能为空）。故意传入非法 JSON，观察 pydantic 报出的结构化错误——然后感慨"这不就是运行时版 zod，还内置在类型里"。

  1. Protocol 鸭子类型：定义一个 SupportsClose Protocol（要求有 close() 方法），写一个函数 cleanup(resource: SupportsClose)，让文件对象、你自定义的类、数据库连接 mock 都能通过类型检查——体会结构化类型 vs 名义类型（继承）的差异。

  2. TypedDict vs dataclass vs pydantic：对同一个"配置对象"场景分别用三种方式建模，从"运行时校验/性能/样板代码/序列化"四个维度对比，写进笔记。

自测问题 ​

  • Python 类型提示在运行时会被检查吗？pydantic 为什么又能检查？
  • Optional[str] 和 str | None 有区别吗？
  • Protocol 和 ABC（抽象基类）的本质区别是什么？
  • 泛型 TypeVar 的 bound= 参数有什么用？
  • Any 满天飞会有什么后果？mypy 的 --disallow-any-expr 是干什么的？
